权威原文的核验原则

  1. 优先政府、立法机构、监管机构与法院原文。
  2. 仅成功打开官方链接，不代表已完成法律事实核验。
  3. 核对文件名、日期、范围与法律状态后才标记已核验。
  4. 找不到原文的事项保留并标记“官方原文待核实”。

MONITOR CONFIGURATION

让监测流程，真正运行

密钥仅保存在服务端。真实数据未接通前，不把演示结果当成采集成果。

01 / 数据源接入

复制项目内 config.example.json 为 config.local.json，填写 DataGuidance 的目标页面和实际页面选择器，以及小宇宙节目的 RSS 地址。

PRD 提到了小宇宙的“现有成功方案”，但没有附带代码。本版提供 RSS 适配接口，仍需接入并验证真实节目源。

DataGuidance 必须在真实站点验证 All 标签、总条数及分页；遇访问控制会停止，不绕过登录或验证码。

02 / AI 分析配置

在项目根目录新建 .env，填写以下服务端环境变量：

OPENAI_API_KEY=你的密钥
OPENAI_MODEL=你账户可用的模型名称

配置后重启本地服务。未配置模型时仍保留原始事项，但相关性与摘要标记为待人工判断。请勿在聊天、前端或公开仓库中粘贴密钥。

03 / 定期监测与云端部署

默认频率：每周一 09:00，北京时间，收集过去 7 天的资讯。WorkBuddy 定时任务负责本地执行；电脑和运行环境须可用。

仓库内附带 GitHub Actions 与 Pages 配置。连接仓库、设置 Secrets 并启用 Pages 后，可转为云端运行。ENABLE_GITHUB_SCHEDULE=true 才会启用云端定时。

切换为云端定时前请停用本地定时，避免重复采集和模型费用。

04 / 运行与信息边界

python server.py --port 8765
python -m monitor.cli run --mode live
python -m monitor.cli verify

网站本地服务仅监听 127.0.0.1。公开 Pages 仅展示结果，不保存密钥、原始全文，也不能直接触发本地采集。公开部署前请审核摘要及公司相关性内容。

本产品用于监管信息整理，AI 分析不构成正式法律意见。
